## Correction strategy

The implementation is intentionally split so the product-capability gap cannot stall unrelated engineering:

1. **Capability route gate** — no native P0-A generation is spent until one zero-cost route supplies every required primitive.
2. **Completion gate** — `scripts/check-d0-completion.mjs` reads the six formal proof receipts and reports activation readiness. Missing or blocked evidence fails closed.
3. **Activation builder** — `scripts/prepare-d0-activation.mjs` can build the exact activation receipt and active image contract only after all six proofs are PASS.
4. **Activation firewall** — any D0 bundle is rejected unless protected main is active and the exact activation receipt is present and digest-bound.
5. **Image-only migration guard** — the October 7 migration is preflighted against the existing SHADOW_VERIFIED execution and a semantic fingerprint. The migration cannot create another execution or change stories, media, Watchlist, book mappings, or other semantics.
6. **Migration verifier** — after six D0 replacements are accepted, verification requires the same execution, identical semantic fingerprint, six locked D0 assets, all six image byte streams replaced, and `semantic_rework=0`.

## Remaining live sequence

When the route matrix first evaluates READY:

1. Run one bounded P0-A capability proof using the newly available route.
2. If P0-A PASS, run the P0-E text/brand stress proof using the existing strict first-attempt prompt contract.
3. Run P0-F on six isolated story packets. Require six exact raw captures, deterministic normalization, six Visual Review v3 PASS receipts, and Set Review v3 PASS.
4. Persist formal P0-D for one exact story-bound final candidate.
5. Run `node scripts/check-d0-completion.mjs`. It must return PASS.
6. Run `node scripts/prepare-d0-activation.mjs`. Review only deterministic receipt/path/hash binding, then merge the activation change through protected CI. No runtime fallback is introduced.
7. Update the four Compiler schedule prompts so future image stages route only through active D0. Proposal 1R remains available only for internal diagrams/fixtures, never reader-story fallback.
8. Prepare the existing October 7 execution with `prepare-image-only-migration.mjs`. Do not allocate a new execution and do not reopen editorial/content stages.
9. Generate and accept six October 7 D0 replacements against the already sealed story semantics.
10. Replace the six image records atomically, rebuild deterministically, deploy, and verify exact live bytes.
11. Run `verify-image-only-migration.mjs`; require PASS and `semantic_rework=0`.

## Stop conditions

Stop rather than weaken the contract if:

- no zero-cost P0-A route is READY;
- exact generated bytes are not available before capsule end;
- a result cannot be inspected from exact persisted pixels;
- any P0-E text/branding rule fails;
- any individual Visual Review v3 fails after the bounded visual-attempt limit;
- the six-image set review fails;
- activation evidence is missing or digest-mismatched;
- October 7 semantic fingerprint changes;
- a second October 7 execution would be required.

A stop preserves every completed proof and accepted immutable asset. It never opens a paid, owner-transfer, same-chat, or Proposal 1R reader-image fallback.
