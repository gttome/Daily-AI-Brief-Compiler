## Callable interface

`node scripts/record-d1-image-event.mjs validate-only INPUT.json` validates retained state and accounting without writes. `emit INPUT.json NEW-batch.json` emits a new, non-overwriting batch. The JSON contains the prior state, attempt log, request, source evidence, their expected canonical hashes, expected branch head, requested engine and observed event. Raw/canonical assets, when needed, are separate relative files next to the input. Arbitrary totals are not input fields.

The CLI reports hashes of the actual loaded executable/modules. A requested engine identity is NOT a verified protected checkout, and local execution is NOT proof that the Work task can call the helper. `publishD1EventBatch` requires actual existing `getHead`, `readFile`, `createCommit` and `updateRef` capabilities. `readFile` returns null only for a verified absent path; access errors must propagate. `updateRef` must enforce the expected head, not merely perform a preceding read. The GitHub connector exposes those existing writer operations. The deterministic publisher must execute through its actual caller; emitting a batch and manually bypassing its replay or immutable-asset checks is not a valid publication path.

## Existing writer caller

`node scripts/publish-d1-image-event.mjs BATCH.json` executes the actual `publishD1EventBatch` with a strict stdio bridge. `scripts/d1-github-writer-host.mjs` is the concrete code-mode host for the existing GitHub connector. It uses only the existing `exec_command` / `write_stdin` and GitHub operations; it adds no network client, credential source, service, task or model route. Load the reviewed host function from the same verified engine source and call `runD1GitHubWriterHost({tools, root, batchPath})` inside the existing outer Work task.

The host uses a raw non-echoing PTY because the actual command tool closes ordinary pipe stdin. Large native image bytes remain in the existing emitted batch file and are read in bounded chunks; stdout carries only validated write indexes and identities. The host creates blobs and one tree/commit on the exact parent, updates the same branch with `expected_sha` and `force:false`, and feeds actual results back into the running publisher. The publisher independently replays the event, checks accepted canonical bytes, fences the head, and verifies final immutable bytes. An access error is never relabeled as a missing file. An unknown write outcome stops for reconciliation without any automatic retry.

Child-process bridge tests exercise the actual publisher, including forged-batch, stale-head, missing canonical-byte, malformed-response and unknown-outcome failures. They establish deterministic implementation behavior, not a future Work invocation or premium-image proof.
