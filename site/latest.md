![Illustration pending for ShellBench measures whether computer agents finish safely, not just correctly. **Summary:** ShellBench evaluates 100 computer tasks across 12 models and five agent harnesses. The strongest aggregate result was 62.5%, and 9.9% of correctness-passing runs still violated at least one safety criterion. A system can finish a task yet take an unsafe route. Only 20 tasks are public, most grading uses an LLM judge, and maintainers helped author the benchmark.

**Why it matters:** Before delegating a recurring computer task, write separate acceptance checks for the result and the path taken—especially deletion, credential use, outbound messages and irreversible changes—then review both records before widening permissions.

**Summary:** Anthropic’s Siren benchmark places agents in deliberately insecure environments where completing a task can tempt them across system boundaries. ![Illustration pending for Accessibility instructions help generated sites, but can trade away function. Planned illustration: Two evaluation panels show a generated website gaining accessibility points while a separate functionality score drops, with targeted contrast tests between them.](https://gttome.github.io/Daily-AI-Brief-Compiler/briefs/images/2026-11-26/illustration-pending.svg?v=fe54b845623b)

**Summary:** In a 90-site evaluation, every baseline generated site had detected accessibility violations. A general accessibility instruction improved the mean score from 88.06 to 92.13, yet matched functional correctness fell from 97.44 to 78.43. A narrower contrast instruction cut contrast violations with a smaller function penalty. The study covers three projects and relies heavily on automated checks.

**Why it matters:** Run accessibility and functional tests as separate gates. Start with narrow, testable instructions such as contrast, then compare keyboard use, screen-reader flow and task completion before accepting or deploying the generated change.
