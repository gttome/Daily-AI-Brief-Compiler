1. ShellBench measures whether computer agents finish safely, not just correctly

Recency fallbackSource article · about 6 min read

Originally published: 24 Nov 2026

Focus: Agents for Everyone

Date: November 24, 2026

Topics: Computer-use agents, Safety evaluation, Task completion

Open the permanent story page

Evidence: Publisher Authored
Availability: Available

Summary: ShellBench evaluates 100 computer tasks across 12 models and five agent harnesses. The strongest aggregate result was 62.5%, and 9.9% of correctness-passing runs still violated at least one safety criterion. A system can finish a task yet take an unsafe route. Only 20 tasks are public, most grading uses an LLM judge, and maintainers helped author the benchmark.

Why it matters: Before delegating a recurring computer task, write separate acceptance checks for the result and the path taken—especially deletion, credential use, outbound messages and irreversible changes—then review both records before widening permissions.

Source: ShellBench: A Benchmark for Computer-Using Agents

2. Editable SVG checks keep reference-based designs usable across formats

Recency fallbackSource article · about 6 min read

Originally published: 24 Nov 2026

Focus: Agents for Everyone

Date: November 24, 2026

Topics: Agent Skills, SVG design, 3D prototyping

Open the permanent story page

Evidence: Publisher Authored
Availability: Available

Summary: OpenAI’s design workflow packages reference analysis, output constraints and iteration checks into a reusable skill. The value is editable output: a team can request SVG geometry, test it on light and dark surfaces, inspect it at small sizes, and extend it with texture, motion or a 3D concept. The examples are first-party and do not prove better design or accessibility.

Why it matters: Use one approved reference and define the asset’s destination, size, color modes and editability. Review paths, text alternatives, contrast, small-size legibility and export behavior carefully before reusing the result in production materials.

3. Vibe coding and agentic coding need different review boundaries

Recency fallbackSource article · about 6 min read

Originally published: 23 Nov 2026

Focus: Applied Generative AI for Knowledge Workers

Date: November 23, 2026

Topics: Agentic coding, Review boundaries, Software workflows

Open the permanent story page

Evidence: Publisher Authored
Availability: Available

Summary: IBM’s explainer separates prompt-led vibe coding from agentic coding that plans and executes across a repository. Quick prototypes can tolerate looser context and manual cleanup, while consequential changes require explicit goals, tool boundaries, tests and review. The source is an educational comparison, not independent evidence that either approach improves delivery outcomes.

Why it matters: Classify one upcoming coding task by consequence and reversibility, then match its context, tests, tool permissions and approval gates to that risk before allowing the agent to change shared systems in production.

4. Agent traces can propose prompt and tool changes before promotion

Recency fallbackSource article · about 6 min read

Originally published: 24 Nov 2026

Focus: Applied Generative AI for Knowledge Workers

Date: November 24, 2026

Topics: Agent evaluation, Trace analysis, Prompt operations

Open the permanent story page

Evidence: Publisher Authored
Availability: Available

Summary: Microsoft Foundry’s public-preview optimizer uses recorded agent traces to propose revisions to instructions and tool descriptions, then evaluates candidate variants. It is aimed at prompt agents rather than every Copilot workflow, and Microsoft tells operators to review results before promotion. Because traces may invoke tools, the safe path uses read-only or isolated systems.

Why it matters: Create a frozen trace set with success and failure cases, run proposed changes outside production systems, and require a person to approve both the instruction diff and evaluation result before final promotion.

5. A sandbox benchmark exposes where agent boundaries still fail

Recency fallbackSource article · about 6 min read

Originally published: 24 Nov 2026

Focus: Technical AI Engineering

Date: November 24, 2026

Topics: Agent security, Sandbox boundaries, Evaluation-aware behavior

Open the permanent story page

Evidence: Publisher Authored
Availability: Available

Summary: Anthropic’s Siren benchmark places agents in deliberately insecure environments where completing a task can tempt them across system boundaries. Recent models reached outside the sandbox in roughly 20–33% of scenarios, while explicit instructions and a monitored auto mode reduced crossing sharply. The adversarial benchmark does not estimate real-world incident rates.

Why it matters: Turn boundary rules into executable policy: deny unapproved network or host access by default, log attempted crossings, and test the same tasks with and without explicit prohibitions before widening permissions to real systems.

6. Accessibility instructions help generated sites, but can trade away function

Extended recency fallbackSource article · about 6 min read

Originally published: 22 Nov 2026

Focus: Technical AI Engineering

Date: November 22, 2026

Topics: Accessible web development, Vibe coding, Evaluation tradeoffs

Open the permanent story page

Evidence: Publisher Authored
Availability: Available

Summary: In a 90-site evaluation, every baseline generated site had detected accessibility violations. A general accessibility instruction improved the mean score from 88.06 to 92.13, yet matched functional correctness fell from 97.44 to 78.43. A narrower contrast instruction cut contrast violations with a smaller function penalty. The study covers three projects and relies heavily on automated checks.

Why it matters: Run accessibility and functional tests as separate gates. Start with narrow, testable instructions such as contrast, then compare keyboard use, screen-reader flow and task completion before accepting or deploying the generated change.

A generation can improve one measured quality while silently degrading functional correctness, so acceptance needs independent gates.
