## 1. What this is — and is not

Daily Compiler Primary publishes a complete editorial Brief at 19:15 America/Chicago for the **next** calendar day. Each new Release 1 edition can publish independently with six accurately described 1200 × 630 generic placeholders and zero native/external image dependency. Never delay, restart, rewrite, or reschedule that publisher to produce images. All non-Primary ChatGPT tasks remain paused. Never revive October 9's terminal SHADOW_FAILED execution, D0, D1, Proposal 1R or retired image lanes.

This file gives a new authorized GitHub-connected Work operator a permanent discovery path for subsequent, optional, **post-publication** premium illustration work. It is generic: it must never be edited to insert tomorrow's date, a pasted story list or a temporary chat link. An index entry or a staged package is **not** evidence that an image is visually approved or published.

Check the SHA-256 of the exact downloaded job bytes against index.editions[].job_sha256, using the JSON file bytes including final newline; do not hash reconstructed JSON or substitute a remembered digest.
3. Read the corresponding immutable source edition bundle at job.source.bundle_url; independently hash its raw file bytes to job.source.bundle_sha256. Inspect the original run's compiler-state.json and its actual publication receipt on the exact source branch/commit. Require SHADOW_VERIFIED / VERIFY, images.mode=images_pending, zero accepted images, matching edition_date/execution_id/branch/bundle SHA, and a genuinely live dated Brief and six permanent stories. Do **not** infer qualification from a CI green check, historic preview, branch name or an old completion narrative alone.

The durable image job is generated from the original, already-published semantic bundle **only after** independent live publication, including a 17-object October 8 hash gate, has completed. The source bundle remains immutable; the job carries its branch, exact source commit, execution, bundle SHA-256, full six Compiler story objects, publisher URLs and original dates, source reading evidence, figure alt intents, verified media context, Watchlist/book links and image-quality rules. ## 3. Quality and editorial scope

Work from the six **different** story records in job.stories. Within each story's generation context, use that story's complete Compiler article, primary publisher URL/original date, verified full-source reading scope, image_alt_intent and story-only text spec. Consult the immutable original source as needed for accuracy. Do not bring other stories, prior Brief images, repository orchestration, branch IDs or chat history into a story-only generator conversation.

Required deliverable: six independent, exact 1200 × 630 **PNG** high-quality explanatory mechanism diagrams, each visually distinct, commissioned professional textbook/editorial finish, white or near-white background. Use the benchmark at https://github.com/gttome/Daily-AI-Brief-Compiler/blob/main/docs/D1-PRODUCTION-IMAGE-BENCHMARK-PROFILE.md : at least 12 causal components, 3–5 major regions, 2 or more meaningful substages in the dominant mechanism, 2 or more secondary evidence/constraint/feedback relationships, dimensional technical detail, 80–90% useful occupancy, true explanatory hierarchy.

Reject pseudo-text, unapproved characters, stock photos, humans/faces/avatars, branding/logos, decorative dashboards, flat repeated boxes, sparse placeholder art and unsupported factual specifics. job.stories[].visual_specification.visible_text_allowlist starts EMPTY and labels_authorized is false: **no visible text is authorized by the input packet**. A separate explicit, version-bound approval is required to introduce an exact visible-text allowlist; do not generate your own label approvals. Images must remain faithful to original publisher evidence, not merely attractive.

Before any acceptance, view the **exact persisted Git PNG pixels** and inspect mechanism, fidelity, labels, clipping, distinguishability and quality. A Git commit, correct dimensions, six filenames or a signed JSON claim alone does not establish visual PASS. Record genuine review context, checked SHA-256, reviewer and independent six-image set review. If the platform cannot inspect persisted pixels, the candidate remains NOT_ACCEPTED. Do not claim premium status from a fabricated receipt.

## 4. Stage exactly six immutable binaries

The job binds one approved intended destination per story:

    external-image-packages/YYYY-MM-DD/images/<exact-story-id>.png

Create binary blobs through the authenticated, authorized GitHub capability, on a new **unprotected staging branch** based on freshly read protected main. Never push directly to main, Pages history or a public reader branch. After uploading, read each actual Git blob back by the exact commit and verify (a) valid PNG signature and IHDR, (b) exact 1200 × 630 pixels, (c) byte count, (d) SHA-256 and (e) Git blob SHA-1 from the exact persisted byte stream. Require six distinct story IDs, six independent nonidentical image hashes, and an original story-bound review receipt per PNG.

A release candidate must lock the original job digest, edition, execution, content bundle, exact source SHA, review evidence, six binary paths/hashes, and the current pre-replacement Pages history SHA. Never overwrite accepted_locked assets, reuse a stale package, silently replace another edition, reclassify a legacy failed execution or re-run semantic research. Idempotent retry means read/reuse exact validated bytes.

The protected Compiler-side image staging/replacement commands and package schema are Iteration 2 engineering deliverables. **Until their own protected PR/CI verification and genuine external six-image test have passed, treat this section as an interface contract, not an enabled production command.** No image asset can be accepted by this document itself.

## 5. Protected post-publication release

Only after an owner-authorized, genuinely visually approved complete six-image package exists, submit the narrow package/replacement change through a protected Compiler PR. Require exact-head validate CI and a normal protected merge with no bypass. The deterministic publisher must:

- confirm the original publication and digest again, and prevent duplicate correction revisions;
- patch **only** the six pending image positions in the dated Brief, six permanent story pages and (only if still the matching latest edition) the homepage; keep original story text, source links, videos, podcasts, Watchlist, all four books, ratings/share/feedback IDs, archive, latest chronology and feeds otherwise identical;
- deploy exact bytes to real GitHub Pages without generating images or restarting any ChatGPT producer;
- independently download each new live PNG and verify exact SHA-256/byte count, check the dated Brief and all six story image references on desktop and mobile, and verify unmodified archive, media, feedback, sharing and other site routes;
- recheck **all 17** protected October 8 live public objects, including all six immutable historical PNGs, against the pinned SHA-256 list in scripts/verify-publication-preservation.mjs;
- persist original first-publication provenance and a separate revision/CI/Pages/verification receipt. Do not call the image set ACCEPTED or the release complete until those real gates pass.

If any build, tool, GitHub authentication, browser or external image capability blocks progress, preserve the independently verified work and current published placeholder Brief. No fallback generator, new scheduler, task rearm, Work dependency for Primary or speculative media is permitted.
